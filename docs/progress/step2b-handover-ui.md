# Step 2b：交接摘要畫面（前端）

## 這次做了什麼
- 聊天視窗上方新增「📋 交接摘要」面板（`my-ai-ui/src/HandoverPanel.tsx`），呼叫 2a 的 `GET /api/v1/handover/summary`。
- **甜甜圈圖**顯示任務狀態分布（已完成 / 進行中 / 卡關 / 未開始），中央顯示任務總數；下方列出「已完成 N / 總數」與去重合併了幾筆。
  - 與團隊討論後決定：交接是「各狀態佔比」，用甜甜圈圖比折線圖貼切；折線圖保留給 Step 4 的每週趨勢。
- **待交接任務清單**：未完成的任務依優先度（或進度）排序，每筆有優先度標籤、進度條、最後更新日、出現次數；卡關任務以橘底標出原因。已完成任務收合在「已完成任務」。
- **權限**：員工只會看到自己的摘要；主管多一個「作者姓名」輸入框，留空＝自己。後端依 Firebase 登入帳號判斷，前端只是呈現。
- 甜甜圈圖用原生 SVG 繪製，沒有新增圖表套件（少一個相依、建置更穩）。圖表分段的計算寫在 `src/handover.ts`，數字全部來自後端 SQL，前端不計算統計。
- 新增 `VITE_HANDOVER_API_URL`（選填，預設由 `VITE_CHAT_API_URL` 推導，不用改 `.env` 也能用）。
- 「新增日報」成功後，訊息會提示可按「重新整理」查看交接摘要。

```powershell
# 終端機 1：Qdrant（docker compose up -d）、終端機 2：後端、終端機 3：前端
cd my-ai-ui
npm run dev
```
